## 5. 获准实施后的步骤与产物

1. **刷新与冻结证据**：重新读两个 AGENTS.md、Issue/PR 状态、远端 refs 和工作区修改；记录完整 SHA 与差异清单。新建独立 checkout，不搬走、不覆盖当前 4 个既有未跟踪治理文件。
2. **只读核对线上来源**：核对服务/环境、流量版本、镜像 digest、构建 ID/commit、跟踪分支、构建上下文、Dockerfile、端口/探针及配置修订号。对数据库只查 schema、revision 和重复计数；公开文档不写生产数据明细。缺少访问或证据则标“待核实”，暂停发布切换，不能猜测映射。
3. **建立候选分支及差异台账**：从第 3 节固定业务 SHA 起步，纳入本任务文档/CI；在 #2 获准合并后合并新的 master，保留两条提交历史。记录每个冲突的取舍；业务文件原则上原样保留，必要修正先更新计划范围。
4. **增加发布说明与记录模板**：后端拟增加 `docs/deployment/release-baseline.md`、`release-record.template.json`、必要校验脚本；README 链接统一入口；本计划同步更新状态。实际文件结构可在实施时按现有仓库惯例微调，字段与门槛保持。
5. **扩展 CI**：保留治理检查，新增运行代码验证与容器验证；PR 触发到 master，候选 codex 分支可运行，不带生产凭据、不自动部署。对记录模板校验必需字段及格式，真实发布记录未完成时不得标“可发布”。
6. **提交 PR**：关联 #4，列清原业务差异与本任务新增内容、CI 证据、未解决风险、数据库兼容和镜像回退步骤；依赖 #2；交由 Master 审阅。CI 通过后仍等待具体 PR 的明确合并授权。
7. **授权后分阶段操作**：先获准合并 #2，再获准合并 #4 并记录 M4；随后才是另获授权的分支保护设置、云托管切换/发布。每个阶段记录结果与停止条件。若 #4 已合并但线上未切换，明确标为“源码收敛完成，生产切换待授权/核验”，不声称发布已完成。

### 发布记录的最低字段

- 记录 ID、状态（draft/verified/deployed/rolled_back）、时间及操作者、Issue/PR 链接、对应授权记录。
- source repository、branch、完整 commit SHA、业务/治理来源 SHA、CI 运行链接与结果。
- build ID、构建上下文/Dockerfile、基础镜像 digest、最终镜像引用与 sha256 digest；只写 tag 不足以定位镜像。
- 目标服务/环境的受控标识、实际跟踪分支、流量版本及比例、容器端口、启动方式、探针。
- 配置修订号或受控备份引用、环境变量键清单、secret 的版本引用；禁止填真实密码、JWT 或 token，不对低熵 secret 做公开哈希。
- 数据库迁移 revision 前/后值、schema 检查摘要、备份/恢复演练引用、候选及回退镜像兼容结论。
- 回退镜像 digest、对应 source SHA 与配置修订、触发条件、执行步骤、验证与负责人。
- 缺失项和阻断原因；未知字段必须明确标记 unknown，只有字段与证据齐全才允许 verified。

生产配置备份、数据库备份和详细线上记录存放既有受控位置；公开后端仓库只提交脱敏模板及说明，不能把本地审计材料或 env 目录带入 PR。

## 7. 发布切换、风险与回退

### 发布前置条件及停止条件

- Master 已分别授权具体 PR 合并及本次生产切换范围；#2 → #4 完成，记录 M4；不向原云托管跟踪分支直接推送。
- 当前线上镜像与 source SHA、现有配置、数据库 revision 已确定；候选与回退镜像均通过隔离兼容验证。
- 保留可用的旧镜像 digest、对应配置修订和数据库备份，完成恢复演练；在发布窗口前核对备份可用性。
- 若控制台无法保证改跟踪分支不会立即构建/发布，按一次生产发布操作对待；事先确定是否支持暂停触发或先构建不切流，不能假定“只改设置”无影响。
- 实际 SHA、端口、schema、配置、CI 或回退证据任一不一致，停止切换并更新记录；迁移前出现重名分类不得现场删数据处理。

### 回退分层

1. **计划阶段**：只新增双份计划与领取记录；如方案调整，修订计划和 Issue 状态即可，无运行或数据库变化。
2. **实现未合并**：修改或关闭本 Issue PR，保留证据和分支，不影响生产。
3. **合并但未发布**：优先修正文档/CI。若须撤销收敛，走新的 revert PR 并由 Master 授权；不能盲目把默认源码退回旧 master 后继续接收修复。
4. **发布后异常**：按已核验的上一可用镜像 digest 恢复流量/版本，同时恢复它对应的端口、探针及兼容配置，验证健康、只读接口及后管入口；记录回退时间、原因、commit/digest/配置及结果。阈值使用发布前确认的监控基线，不凭空给出线上比例。
5. **数据库**：默认保留已经执行的兼容性扩展，禁止因回退代码自动执行 downgrade、DROP、重跑 schema.sql 或恢复旧库覆盖发布后的新数据。旧镜像不能兼容当前 schema 时不得使用；选择预先验证的兼容镜像或准备修复版本。若只能恢复数据库，须在独立恢复环境验证并明确停写、数据补偿与 Master 授权后另执行。

旧 `bffe5a0` 不作为默认回退目标；只有单独验证代码、依赖、schema、端口和配置兼容后才可能使用。当前 `20260822_01` downgrade 不撤销结构，数据库恢复与镜像回退必须分别评估。
